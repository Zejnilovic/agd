Why agd · general notes

  1. Copy a good agent setup into ten projects, and you have ten setups.
  2. Copy a new version over them, and you wipe out what each project changed.
  3. So nobody updates, and the copies drift apart.

agd keeps a setup in one git repository, installs it into every project at a version, and updates it without touching what each project made its own.

Section A–A · one installed file

The source's lines update. The project's lines stay.

agd records exactly what it installed, so it can tell your changes from the source's. Each installed file has parts that belong to the source, and parts that belong to your project.

  • From the source. agd update replaces it with each release you take.

  • The project's, in red pencil. An agent's model: and tools:, and a ## This project section. Every update keeps them.

  • Anything else you change is an edit, clouded like a revision. agd never overwrites it: diff it, merge it or reset it, your call.

Parts list · what you get

ItemPartCommands
1

Versioned like a dependency

Sources publish releases as git tags. A project installs one, records it in .agd.lock, and moves on with one command, with links to the release notes.

 agd status
agd update
2

Plain files, in your repository

No plugin and no runtime. Agents read the files as they are, people review them in pull requests, and git keeps their history.

 git diff
3

Never overwrites your work

Edited files are left alone and reported. See both sides of a change, merge the source's changes into yours, or take the source's file.

 agd diff
agd merge
agd reset
4

Take only what you need

Packs group a source's files and bring the packs they require. Add and remove them later, and leave out single files with .agd-ignore.

 agd init --with flask,react
5

Stack setups

Install your team's agents on top of agentic-defaults. Where two sources ship the same path, you choose which one wins.

 agd init your-org/team-kit
6

Small enough to trust

One bash script that needs only git, on macOS, Linux and Windows. It copies files, and never runs code from a source.

 bash 3.2+ · git

Assembly sequence

  1. STEP 01

    Install

    agd init copies the latest release of a source into your project, and writes .agd.lock.

  2. STEP 02

    Commit

    Commit the files with the lock, so the whole team works with the same setup.

  3. STEP 03

    Make it yours

    Pick models, limit tools, add your project's rules. Add agents of your own next to the source's.

  4. STEP 04

    Update

    agd status shows what a new release changes; agd update takes it. Your parts stay.
